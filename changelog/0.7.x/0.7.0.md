# 0.7.0 — 2026-11-16

## Added

- **`oecd_get_dimension_values`** `available_only` and `key`: list only the codes with data, or only those with data given the other segments of `key`, read on the root that serves the dataflow's data. The result gains `available_only`, `time_range`, and `observation_count`; a malformed `key` fails `invalid_key` ([#47](https://github.com/cyanheads/oecd-mcp-server/issues/47)).
- **`oecd_query_dataset`** names the cause of a `no_results`, such as a code with no data or one that matches only by case. The diagnosis spends at most 10 s of the call's budget, so a longer `Retry-After` is never waited out, and when it fails the plain `no_results` stands ([#47](https://github.com/cyanheads/oecd-mcp-server/issues/47)).
- **`oecd_search_datasets`** `notice` output field, set when an over-cap `limit` is clamped ([#51](https://github.com/cyanheads/oecd-mcp-server/issues/51)).
- **`OECD_CLAMP_LIMITS`** (default `true`), declared in `server.json`, `manifest.json`, and `.env.example` ([#51](https://github.com/cyanheads/oecd-mcp-server/issues/51)).
- **Structure cache**: decoded structure responses are cached for `max-age − Age`, bounded at 64 MiB with LRU eviction, one cache per process. A repeat `oecd_get_dataset_info` goes from 2 requests to 0, and a repeat catalog read from 1 to 0. `oecd_list_agencies` sends one agency-scheme request, then none on repeat ([#49](https://github.com/cyanheads/oecd-mcp-server/issues/49)).
- **Cached delegated reads**: a repeat read of a delegated dataflow whose datastructure only its delegated root holds sends no request while the cached answer is fresh ([#49](https://github.com/cyanheads/oecd-mcp-server/issues/49)).
- **Shared structure loads**: a call that joins another call's in-flight load keeps its own budget. If the shared load runs out of its budget first, the joining call starts a fresh load with the time it has left ([#49](https://github.com/cyanheads/oecd-mcp-server/issues/49)).

## Changed

- **Breaking: `oecd_query_dataset` rows** no longer carry `source` or any column whose value is the same on every row of the result; those arrive once in the new `constant_columns` (one `{ code, label }` per column, always present). Every coded component now carries `<ID>_code` beside its label ([#48](https://github.com/cyanheads/oecd-mcp-server/issues/48)).
- **Breaking: `non_production`** is removed from `oecd_search_datasets` (`dataflows[].non_production`), `oecd_get_dataset_info`, and the `oecd://dataflow/{agency_id}/{flow_id}` resource; it was `false` for every dataflow ([#46](https://github.com/cyanheads/oecd-mcp-server/issues/46)).
- **Breaking: `oecd_search_datasets`** matches a query token only where it starts a word: at the start of the text, after a separator, or at a lowercase-to-uppercase step. A token found only inside a word now returns `no_match` (`conomic` matched 359 dataflows and now matches none), and a digit run directly after a letter is not a word start (`pm 2.5` no longer matches `PM2.5`; `pm2.5` does). A token that opens on a separator, such as `&`, still matches anywhere ([#50](https://github.com/cyanheads/oecd-mcp-server/issues/50)).
- **Breaking: `oecd_dataframe_query`** (`@cyanheads/mcp-ts-core` 0.13.22's SQL gate) refuses a column alias or CTE named after any of DuckDB's 35 internal metadata views other than `sqlite_master` (quoted and uppercase spellings included), and a direct `SELECT * FROM` of `pg_am`, `pg_collation`, or `pg_tablespace`, which 0.6.1 answered with engine metadata rows.
- **Breaking: `oecd_dataframe_query`** on DuckDB 2: an integer `//` or `%` by zero fails with `sql_execution_error`, where 0.6.1 returned NULL. `TRY(…)` around the expression returns NULL, and the error's recovery says so.
- **`oecd_query_dataset`** sorts rows by each dimension's code in key order, `TIME_PERIOD` last. The staged canvas table keeps every column, `source` and the `_code` columns included ([#48](https://github.com/cyanheads/oecd-mcp-server/issues/48)).
- **`oecd_search_datasets`** ranks results in three tiers (every token in the name, tokens split between name and description, description only), each in catalog order ([#50](https://github.com/cyanheads/oecd-mcp-server/issues/50)).
- **`limit`** above the cap is clamped and served at the cap with a `notice`, and logged and counted (`oecd.count_input.clamps`), instead of being rejected. Caps and defaults: `oecd_search_datasets` 2,000 / 20, `oecd_get_dimension_values` 10,000 / 50, `oecd_dataframe_query` 1,000 / 100; the 0.6.1 maxima were 100, 500, and 10,000, with dataframe values over 1,000 served at 1,000 ([#51](https://github.com/cyanheads/oecd-mcp-server/issues/51)).
- **`OECD_CLAMP_LIMITS=false`** advertises and enforces the caps as strict maxima, so `oecd_dataframe_query` rejects a `limit` above 1,000 ([#51](https://github.com/cyanheads/oecd-mcp-server/issues/51)).
- **`oecd_dataframe_query`** no longer cuts a page at 1 MiB: output size is the caller's `limit`.
- **`oecd_dataframe_query`** value changes on DuckDB 2: unsigned casts saturate or return NULL differently (`TRY_CAST(-0.3::DOUBLE AS UTINYINT)` is 0, `TRY_CAST(255.5::DOUBLE AS UTINYINT)` is NULL); out-of-domain math returns `NaN` or `-Infinity` instead of failing (`sqrt(-1)`, `ln(0)`); `skewness()` of a constant column is NULL; `mode()` tie-breaks differ; `CAST(1e400 AS DOUBLE)` returns `Infinity` instead of failing; approximate estimators and `SAMPLE` pick differently.
- **`range()` and `generate_series()`** with constant arguments answer in `oecd_dataframe_query` (mcp-ts-core 0.13.20).
- **`SHOW <table>`** answers on DuckDB 2 (mcp-ts-core 0.13.19), and `SHOW` / `DESCRIBE` of a missing table report `table_not_found` (0.13.21).
- **`initialize`'s `serverInfo`** carries the server description (mcp-ts-core 0.13.21).
- **Captured upstream error bodies** stay off `structuredContent.error.data` (mcp-ts-core 0.13.22).
- **Node.js below 24**: the server refuses to start (mcp-ts-core 0.13.20).
- **Error contracts and descriptions**: `rate_limited`'s `when` covers a `Retry-After` longer than the call's budget; the `no_match` recovery explains word-start matching; `dimension_not_found` names the time dimension; the time-dimension description names `start_period` / `end_period`; the server `instructions` name `available_only`, `<ID>_code`, and `constant_columns`.
- **`oecd-guide` skill** 1.2: gates updated for codes beside labels and `constant_columns`, availability reads, word-start search, and the removed `non_production` flag.

## Fixed

- **Upstream budget**: each tool call and the dataflow resource get one budget of max(50 s, `OECD_TIMEOUT_MS`). Retries share it, and when it runs out the caller gets `upstream_timeout` (stub-measured at 50.0 s). A deadline reached after a 429, or a `Retry-After` longer than the time left, reports `rate_limited` ([#40](https://github.com/cyanheads/oecd-mcp-server/issues/40)).
- **`upstream_unreadable`** (not retryable) is declared on every OECD-reaching definition. It covers a 200 whose body can't be decoded (an HTML page, a non-JSON body, a structure the decoder can't read) and a codelist id outside the SDMX character set. An `upstream_error` message names the status OECD answered, as `OECD answered HTTP <status>: <text>`, using the page `<title>` for HTML, and a structure endpoint's 422 and any 501 map to `upstream_error` ([#43](https://github.com/cyanheads/oecd-mcp-server/issues/43)).
- **`oecd_query_dataset` values** were off by 10^6 where `UNIT_MULT` sits above the observation level. Dataset-level and dimension-group attributes are now read, and so is `dimensions.dataSet`; `UNIT_MULT` applies at any level, so values carry their `value_scale` (DF_PU's CAN `value` 7539000 with `value_scale` 1e6) ([#44](https://github.com/cyanheads/oecd-mcp-server/issues/44)).
- **Structure resolution**: a combined `flow_ref` resolves through `GET /dataflow/{agency}/{id}?references=datastructure`, so a dataflow id OECD doesn't publish is `dataflow_not_found` (`DF_IALFS_UNE_MM`). The datastructure revision the dataflow references is used: `DF_UOE_FIN_NATURE` has 8 dimensions from revision 1.0, `MEASURE` first, where 0.6.1 described 9 from 3.2, including `Q_SHEET`. Delegated roots resolve dataflow-first too ([#45](https://github.com/cyanheads/oecd-mcp-server/issues/45)).
- **`oecd_query_dataset`** against a non-http(s) base URL fails with `invalid_url`.
- **A dimension key rejected for its characters**, before any request is sent, no longer says OECD rejected it.
