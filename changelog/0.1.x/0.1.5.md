# 0.1.5 — 2026-08-09

## Fixed

- **`decodeObservations`** applies `UNIT_MULT` as a base-10 exponent to `value` instead of dropping it — US GDP for 2022 previously returned `26054.614` and now returns `26054614000000`, the figure as OECD measures it. Every row carries `value_scale`, the divisor back to the published magnitude. A code outside the codelist's exponent range (`9999`, meaning ".") or a non-numeric code leaves the value unscaled ([#9](https://github.com/cyanheads/oecd-mcp-server/issues/9)).
- **`OecdDataService.fetchData`** routes through the shared `fetchOecd` boundary — a 422/400 rejection (wrong key arity, unparseable period) now surfaces OECD's own explanatory text instead of a generic "non-JSON response" fault, and a 503/429/408 gets its retries instead of costing a single attempt ([#10](https://github.com/cyanheads/oecd-mcp-server/issues/10), [#18](https://github.com/cyanheads/oecd-mcp-server/issues/18)).
- **`format()`** on `oecd_query_dataset` renders every row up to a shared `PREVIEW_CHARS` budget instead of a flat 10-row cap, on both the DataCanvas and no-canvas paths ([#11](https://github.com/cyanheads/oecd-mcp-server/issues/11), [#19](https://github.com/cyanheads/oecd-mcp-server/issues/19)).

## Added

- **`oecd_query_dataset`** rows carry every declared SDMX observation attribute (`OBS_STATUS`, `PRICE_BASE`, `DECIMALS`, `UNIT_MULT`, …) as a flat column, resolved from `structures[0].attributes.observation` the same way dimensions already are; an attribute absent from a slice is omitted rather than reported as `null` ([#9](https://github.com/cyanheads/oecd-mcp-server/issues/9)).
- **`content_table_capped`** / **`content_table_rows`** enrichment fields disclose when the rendered table stopped short of the result on the no-canvas path — distinct from `truncated`, which still means "the rest is on DataCanvas" ([#11](https://github.com/cyanheads/oecd-mcp-server/issues/11), [#19](https://github.com/cyanheads/oecd-mcp-server/issues/19)).
- **`oecd_query_dataset`** contract gained `invalid_period`, `rate_limited`, `download_limit`, `upstream_timeout` and `upstream_unavailable` reasons, each with its own recovery — a request-rate throttle and a download-size throttle carry opposite advice (wait, versus shrink the query) ([#10](https://github.com/cyanheads/oecd-mcp-server/issues/10), [#18](https://github.com/cyanheads/oecd-mcp-server/issues/18), [#21](https://github.com/cyanheads/oecd-mcp-server/issues/21)).
- **`src/services/oecd-http/oecd-http.ts`** — shared fetch boundary for both SDMX services, carrying the `Retry-After: 0` and 5xx-as-`ServiceUnavailable` corrections previously local to the structure service.

## Changed

- **`oecd_query_dataset`**'s `canvas_id` / `table_name` / `truncated` descriptions now name all three outcomes (canvas off, canvas on but result fits, canvas on and result spills) instead of implying a `canvas_id` always comes back ([#7](https://github.com/cyanheads/oecd-mcp-server/issues/7)).
- **`spillover()`**'s canvas registration now passes an explicit schema built from the decoded columns, so a sparse attribute column that resolves on no row inside DuckDB's sniff window still registers on the table.
- **README**, **docs/design.md**, and **.env.example** reconciled with the corrected output shape and `CANVAS_PROVIDER_TYPE`'s actual effect on the no-canvas cap.
