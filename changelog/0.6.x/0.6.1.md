# 0.6.1 — 2026-11-02

## Added

- **`oecd_dataframe_query` `limit`** (1–10,000, default 100): served up to 1,000 rows per call; a larger value is served at 1,000 with a `notice` naming both ([#36](https://github.com/cyanheads/oecd-mcp-server/issues/36)).
- **`oecd_dataframe_query` `truncated`** output field and `notice`: `truncated: true` marks a result with more rows than came back, and the `notice` names how to reach the rest (aggregate, page with `ORDER BY … LIMIT … OFFSET`, raise `limit`); `truncated` is omitted when the result is complete ([#36](https://github.com/cyanheads/oecd-mcp-server/issues/36)).
- **`oecd_dataframe_query` `query_timeout`** error: a query still running after 30 seconds is stopped.
- **`oecd_query_dataset` `canvas_id`** declares `canvas_not_found`, with a recovery that says to retry without the id and re-stage the tables an expired canvas held.

## Changed

- **`oecd_dataframe_query`** called with just `{canvas_id, sql}` now returns at most 100 rows (it used to return up to the canvas row limit, 10,000 by default), with `truncated: true` and a notice when the result has more; pass `limit` (up to 1,000) or page with SQL. A result past 1 MiB of row data comes back truncated at a whole row.
- **`oecd_dataframe_describe`, `oecd_dataframe_query`** `canvas_not_found` recovery says the canvas's tables are gone and to re-run the `oecd_query_dataset` calls that staged them.
- **`oecd-guide` skill** 1.1: the SQL-output gate states the new limits, and the label gate warns that regional labels repeat across countries, so regional flows group on `COUNTRY` with `REF_AREA`.

## Fixed

- **`oecd_dataframe_query`** `content[]` rendered the first 50 rows while `structuredContent.rows` carried every returned row; both now carry the same rows, nested values as JSON ([#36](https://github.com/cyanheads/oecd-mcp-server/issues/36)).
- **`oecd_dataframe_query`** returns `column_names`, and names them in the text, for a result with no rows ([#41](https://github.com/cyanheads/oecd-mcp-server/issues/41)).
- **`oecd_query_dataset`** resolves an explicit `canvas_id` before the OECD download, so an unknown or expired id fails as `canvas_not_found` without spending one of OECD's hourly downloads, with this tool's recovery in place of the framework's loop-back hint ([#37](https://github.com/cyanheads/oecd-mcp-server/issues/37)).
- **Response body reads** (data and structure services) go through one reader that keeps the failure's classification: a data body that outlasts `OECD_TIMEOUT_MS` is not retried and returns `upstream_timeout` with its recovery hint, a connection dropped mid-body is retried and ends as `upstream_unavailable`, and only a complete non-JSON body becomes `SerializationError`, after one request ([#39](https://github.com/cyanheads/oecd-mcp-server/issues/39)).
- **Caller aborts** return `RequestCancelled` from both services, including mid-body and during the delegation and concept-name lookups, which used to absorb them ([#39](https://github.com/cyanheads/oecd-mcp-server/issues/39)).
- **Unrequested aborts** that `fetchWithTimeout` reports as `RequestCancelled` while the caller's signal is live are retried as the outage they are, working around [mcp-ts-core#799](https://github.com/cyanheads/mcp-ts-core/issues/799) ([#39](https://github.com/cyanheads/oecd-mcp-server/issues/39)).

## Security

- **`oecd_dataframe_query`** returns at most 1,000 rows and at most 1 MiB of row data per call, and stops a query still running after 30 seconds with `query_timeout`.
