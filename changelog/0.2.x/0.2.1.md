# 0.2.1 — 2026-08-09

## Fixed

- **Delegated dataflows** — 27 of 1,544 flows are catalogued on `/public/rest` as a pointer (`isExternalReference: true`, a `links[]` entry with `rel: "external"`) rather than a definition, delegating to `/sti-public/rest` (14), `/dcd-public/rest` (10), or `/archive/rest` (3). `fetchDataStructure`, `fetchData`, and the `oecd://dataflow` resource now follow that link to the owning root instead of failing — the data endpoint answered 500 for all 27, so `oecd_query_dataset` could serve none of them. `externalServiceRootOf()` (`src/services/oecd-http/external-service-root.ts`) checks the href's origin, scheme, and SDMX path shape against the configured root before any request goes out ([#23](https://github.com/cyanheads/oecd-mcp-server/issues/23)).
- **`fetchCodelist`** and **`fetchConceptScheme`** read from the datastructure's own service root (`OecdDataStructure.serviceRoot`) and at the version its enumeration/`conceptIdentity` URN names (`OecdDimension.codelistVersion`), instead of the configured root's current latest — `oecd_get_dimension_values` was offering codes the referenced datastructure rejects. A version the root no longer serves falls back to latest ([#24](https://github.com/cyanheads/oecd-mcp-server/issues/24)).
- **`fetchData`** checks for a delegated service root before spending its retry budget on a 500 or 404, instead of after three attempts and the framework's backoff — the first pass marks those two statuses `retryable: false`, and a 500 the lookup can't explain resumes its remaining attempts ([#25](https://github.com/cyanheads/oecd-mcp-server/issues/25)).
- A 404 body of `NoRecordsFound` is read as an empty result, matching the existing `NoResultsFound` handling — the sentinel differs by service root for the same "query matched nothing" outcome.
