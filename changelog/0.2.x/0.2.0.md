# 0.2.0 — 2026-08-09

## Added

- **`oecd_list_agencies`** returns a `directorate` field resolved from the OECD agency scheme (`GET /agencyscheme/OECD`) — absent for non-OECD publishers (`ESTAT`, `IAEG-SDGs`) and when the scheme is unreachable ([#16](https://github.com/cyanheads/oecd-mcp-server/issues/16)).
- **`oecd_get_dataset_info`**, the `oecd://dataflow` resource, and `oecd_query_dataset`'s dimension descriptions carry a concept name resolved from the datastructure's concept scheme instead of echoing the dimension id — `INSTR_ASSET` reads as "Financial instruments and non-financial assets" rather than repeating itself. A dimension the scheme does not cover keeps its id ([#13](https://github.com/cyanheads/oecd-mcp-server/issues/13)).
- **`oecd_get_dimension_values`** takes `query` (case-insensitive substring against code and label), `limit` (1–500, default 50), and `offset` to filter and page a codelist ([#6](https://github.com/cyanheads/oecd-mcp-server/issues/6)).
- **`oecd_dataframe_query`** declares a `table_not_found` contract entry, detected off the canvas gate's structured `reason: 'missing_table'` rather than a message substring, and names this server's own tools in its recovery ([#17](https://github.com/cyanheads/oecd-mcp-server/issues/17)).
- **`parseFlowRef`** and every `flow_ref`-accepting tool now accept the bare `{agencyID},{df_id}` form OECD publishes for the 8 dataflows with no datastructure prefix, alongside the combined `{dsd_id}@{df_id}` form.

## Changed

- **`oecd_get_dimension_values`** returns a bounded page of codes instead of the whole codelist — `UNIT_MEASURE`'s 1,164 codes and 66 KB of `structuredContent` are now a 50-code, 1,887-byte page by default. `code_count` reports the size of the returned page, not the codelist.

## Fixed

- **`fetchDataStructure`** falls back from `GET /datastructure/{agency}/{prefix}` to `GET /dataflow/{agency}/{id}?references=datastructure` on a 404, resolving 49 dataflows whose id prefix names a datastructure OECD does not keep in step — `DSD_REG_LAB@DF_RATES` is backed by `DSD_REG_LABOUR` ([#22](https://github.com/cyanheads/oecd-mcp-server/issues/22)).
- **`parseDataflows`** emits the dataflow reference OECD actually publishes instead of synthesizing `{agencyID},{dsd_id}@{df_id}` from the structure URN, making the 8 bare-id dataflows queryable ([#20](https://github.com/cyanheads/oecd-mcp-server/issues/20)).

## Security

- **`SDMX_ID_SAFE`** accepted `.` and `..` as valid SDMX identifiers. An identifier occupies a single URL path segment, so a `flow_ref` such as `OECD.TAD.ARP,..` normalized to the catalog-wide collection endpoint, returned HTTP 200 with roughly 8 MB, and the server handed a datastructure out of that response back as the answer to the requested dataflow — wrong data presented as correct, plus large upstream amplification per call. `SDMX_ID_SAFE` now requires a leading letter or digit. The percent-encoded spelling (`%2e%2e`) bypassed the separate dimension-key guard the same way; a `.`/`..` key (in either spelling) is now rewritten to SDMX's `all` wildcard before the request is built.
