# 0.4.0 — 2026-10-03

## Added

- **`oecd_dataframe_drop`** drops one table or view from a DataCanvas staged by `oecd_query_dataset` and returns its `kind` and the `remaining_tables`; an unknown name fails `table_not_found`, pointing at `oecd_dataframe_describe`.
- **`OECD_DATAFRAME_DROP_ENABLED`** (default `false`) turns the tool on. Off, it is wrapped in `disabledTool()`: omitted from `tools/list` and shown on the HTTP landing page with the enable hint. Exposed as a `user_config` toggle in the `.mcpb` bundle and in both `server.json` npm entries.

## Changed

- **`@cyanheads/mcp-ts-core` 0.13.11 adoption.** Tool error `content[]` now ends with `request <id>` and error `data` carries `requestId` (0.13.10); declared `recovery` hints reach the client from each `errors[]` entry, so the handlers' explicit `ctx.recoveryFor()` forwards are gone, with no change to what clients see (0.13.10).
- **`CANVAS_TEMP_PATH`** now names the parent of a private per-process `mcp-canvas-XXXXXX` scratch directory; existing values keep working (0.13.9).
- **Argument validation** repairs stringified objects and integers sent for string fields, and rejections name the field paths (0.13.9).
- **Client error data** no longer carries server stack traces or request context (0.13.7, 0.13.8).
- **`ctx.log` notifications** honor `MCP_LOG_LEVEL` and mask sensitive fields (0.13.11).
- **Dockerfile** installs production dependencies in a `deps` stage on the build platform, cross-installing for the target with `--os`/`--cpu`, then prunes the musl native bindings the glibc image never loads; base images move to `oven/bun:1.4.2`, and `MCP_FORCE_CONSOLE_LOGGING` is no longer set.
- **`server.json` npm entries** use `runtimeHint: "npx"`; the HTTP entry selects its transport with `MCP_TRANSPORT_TYPE=http` instead of `run start:http` arguments.
- **Package description** reads "from the OECD SDMX API via MCP" in `package.json`, the README, `CITATION.cff`, and the Codex plugin manifest.
- **Repo hygiene**: `.gitignore` and `.dockerignore` ignore every `.env*` file except the examples, `.dockerignore` adds the MCP Registry token files, `.mcpbignore` excludes `docs/idea.md` and `logs/`, the npm tarball excludes `dist/*.mcpb`, CodeQL uploads each language under its `/language:<language>` category, and scripts and framework skills are synced to the 0.13.11 templates.

## Fixed

- **Changelog entries 0.1.5 and 0.2.0** no longer end in a stray closing-tag line, which shipped in the npm tarball.
