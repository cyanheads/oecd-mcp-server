# 0.5.0 — 2026-10-24

## Changed

- **`oecd_dataframe_query`** now rejects SQL using `current_setting`, `current_schema()`, `current_schemas`, `in_search_path`, `query_table`, computed `query()` arguments, or an unqualified `current_schema` column. Use a literal `query()` argument and qualify staged columns such as `o.current_schema`.
- **DataCanvas** is enabled by default for npm and Docker installations, honoring `.env` and exported settings and treating whitespace or unsubstituted placeholders as unset; set `CANVAS_PROVIDER_TYPE=none` to opt out. The portable MCPB bundle explicitly disables it because it omits native DuckDB bindings.
- **Tool text output** preserves Markdown punctuation and multiline upstream values; multiline tables render as JSON columns and rows.
- **Development tooling** syncs framework guidance and audit classification, updates Bun and Docker base images from 1.4.2 → 1.4.4, excludes development files from MCPB, and documents each hosted client's connection format.

## Fixed

- **`oecd_query_dataset`** allocates no canvas for fitting results and releases newly created canvases after failed staging, preserving explicit-ID validation and caller-owned canvases ([#34](https://github.com/cyanheads/oecd-mcp-server/issues/34)).
- **`oecd_query_dataset`** maps OECD's recognized plain-text HTTP 403 key and period rejections to `invalid_key` and `invalid_period` with actionable recovery ([#31](https://github.com/cyanheads/oecd-mcp-server/issues/31)).
- **Spill guidance** names the returned canvas and table and directs callers through `oecd_dataframe_describe` before `oecd_dataframe_query` on both response surfaces ([#30](https://github.com/cyanheads/oecd-mcp-server/issues/30)).
