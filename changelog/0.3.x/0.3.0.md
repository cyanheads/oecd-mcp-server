# 0.3.0 — 2026-08-10

## Added

- **`upstreamRefusal()`** in `src/services/oecd-http/oecd-http.ts` reads a terminal OECD failure into one of five reasons — `rate_limited`, `upstream_timeout`, `upstream_unavailable`, `upstream_redirect`, `upstream_error` — now declared identically by `oecd_list_agencies`, `oecd_search_datasets`, `oecd_get_dataset_info`, `oecd_get_dimension_values`, `oecd_query_dataset`, and the `oecd://dataflow/{agency_id}/{flow_id}` resource ([#29](https://github.com/cyanheads/oecd-mcp-server/issues/29)).
- **`oecd://dataflow/{agency_id}/{flow_id}`** declares an `errors[]` contract for the first time — `invalid_flow_ref`, `dataflow_not_found`, and the shared upstream five — with `data.reason` and `data.recovery.hint` on every failure ([#27](https://github.com/cyanheads/oecd-mcp-server/issues/27)).

## Changed

- **`oecd_get_dimension_values`** — an unparseable `flow_ref` now reports `invalid_flow_ref` (ValidationError) instead of `dataflow_not_found` (NotFound), matching `oecd_get_dataset_info`, `oecd_query_dataset`, and the dataflow resource. Breaking for a caller keyed on the old code ([#28](https://github.com/cyanheads/oecd-mcp-server/issues/28)).
- **`oecd://dataflow/{agency_id}/{flow_id}`** — the same reference-parsing failure moves from a bare `NotFound` thrown via `notFound()` (no `data.reason`, no recovery hint) to declared `invalid_flow_ref` ([#27](https://github.com/cyanheads/oecd-mcp-server/issues/27)).
- **`upstream_error`** no longer declares `retryable`, so `data.retryable` is omitted rather than sent as `true`; the reasons that are actually transient — `rate_limited`, `upstream_timeout`, `upstream_unavailable` — carry `retryable: true` in its place ([#29](https://github.com/cyanheads/oecd-mcp-server/issues/29)).
- **`oecd_list_agencies`** and **`oecd_search_datasets`** no longer restate every remaining structure-API failure as `upstream_error`. `InternalError`, `SerializationError`, and any `ValidationError` reaching the boundary now bubble undeclared instead of being relabeled as an OECD refusal — deliberate, recorded in `docs/design.md` ([#29](https://github.com/cyanheads/oecd-mcp-server/issues/29)).
- **`oecd_get_dimension_values`** and **`oecd_query_dataset`** — `invalid_flow_ref`'s recovery hint is reworded to match `oecd_get_dataset_info` verbatim and now includes a worked example (`"OECD.SDD.NAD,DSD_NAAG@DF_NAAG_I"`).

## Fixed

- **`oecd://dataflow/{agency_id}/{flow_id}`** — a malformed percent-escape in `{flow_id}` (e.g. `%ZZ`) previously reached the handler as an unhandled `URIError`; it now reports `invalid_flow_ref` like any other unparseable reference.
- **`oecd_get_dimension_values`** — the codelist fetch that runs after the datastructure resolves now passes through the same upstream-refusal ladder as the datastructure call; a throttle or outage on that second request previously escaped the error contract entirely.
